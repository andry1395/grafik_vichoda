# График объектов 2026

Веб-приложение для администратора и сотрудников. На текущем этапе все данные хранятся **только в localStorage** в одном ключе: `scheduleAppData`.

## Структура проекта

```text
src/
  components/
    Layout.tsx
    ScheduleTable.tsx
  pages/
    AdminMonthPage.tsx
    EmployeesPage.tsx
    ObjectsPage.tsx
    MePage.tsx  # страница просмотра (свои и коллег)
  services/
    dataService.ts
  utils/
    constants.ts
    date.ts
  types.ts
  App.tsx
  main.tsx
  styles.css
```

## Что реализовано

- Маршруты:
  - `/admin/2026/01` ... `/admin/2026/12`
  - `/admin/employees`
  - `/admin/objects`
  - `/viewer` — страница сотрудников (просмотр своих и коллег)
- Русская локализация интерфейса и дней недели.
- Таблица графика: сотрудники по вертикали, дни месяца по горизонтали.
- Выбор значения в ячейке:
  - объект
  - спец-значения: Выходной (В), Отпуск (О), Больничный (Б), Учеба (У)
- Массовое редактирование:
  - выделение диапазона мышью
  - кнопки: «Проставить выбранное», «Очистить выделенное»
- Поиск сотрудника в месячном графике: отображаются только строки найденных сотрудников.
- Экспорт текущего месяца в XLSX кнопкой «Выгрузить XLSX» (CSV-совместимый формат для Excel).
- Редактирование доступно только после ввода пароля администратора.
- Подсветка выходных (суббота/воскресенье).
- Админ-страницы сотрудников и объектов:
  - добавление
  - деактивация/активация
- Публикация месяца:
  - при публикации пустые ячейки автоматически становятся «Выходной»
- Страница сотрудников (`/viewer`):
  - просмотр своего графика и графиков коллег
  - поиск сотрудника по ФИО
  - только опубликованные месяцы, read-only

## Как открыть проект

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Запустить dev-сервер:
   ```bash
   npm run dev
   ```
3. Открыть URL из терминала (обычно `http://localhost:5173`).

## Где лежат данные

Все данные лежат в localStorage в ключе:

- `scheduleAppData`

Структура соответствует формату:

```json
{
  "employees": [{ "id": "...", "full_name": "...", "active": true, "token": "..." }],
  "objects": [{ "id": "...", "name_ru": "...", "short_ru": "...", "active": true }],
  "months": {
    "2026-01": {
      "status": "draft",
      "entries": {
        "employeeId_2026-01-01": {
          "kind": "OBJECT",
          "object_id": "..."
        }
      }
    }
  }
}
```

## Как очистить localStorage

В DevTools браузера (Console):

```js
localStorage.removeItem('scheduleAppData');
```

или полностью:

```js
localStorage.clear();
```

## Как потом подключить БД/API

Архитектурно подготовлен единый слой данных: `src/services/dataService.ts`.

Сейчас UI вызывает только методы `dataService`, а не работает с localStorage напрямую.
Чтобы перейти на backend:

1. Сохранить интерфейс методов `dataService`.
2. Заменить реализацию `getFromStorage/setToStorage` на `fetch/axios` запросы.
3. Добавить асинхронность (`Promise`) для методов сервиса.
4. На UI-слое оставить те же вызовы, добавив обработку загрузки/ошибок.

Такой подход позволяет сменить источник данных без масштабного переписывания компонентов.


## Деплой на GitHub Pages (чтобы не было ошибки `/src/main.tsx`)

Если в браузере видно запрос к `/src/main.tsx`, значит опубликована **исходная** версия `index.html`, а не собранный `dist`.

Правильно так:

1. Установить зависимости и собрать проект:
   ```bash
   npm install
   npm run build
   ```
2. Публиковать содержимое папки `dist/`, а не файлы из корня репозитория.
3. Для этого проекта уже настроены:
   - `base: '/grafik_vichoda/'` в Vite (корректные пути для GitHub Pages);
   - `HashRouter` (роутинг работает на статическом хостинге без backend rewrite).

После деплоя открывайте:

- `https://andry1395.github.io/grafik_vichoda/`



## Пароль администратора

Для доступа к редактированию админ-страниц требуется пароль:

- `admin2026`

После входа сессия сохраняется в localStorage (`scheduleAdminUnlocked`). Кнопка «Выйти из админ-режима» сбрасывает сессию.

## Страницы

- `/viewer` — страница сотрудников: можно смотреть свой график и графики коллег, фильтровать по ФИО и месяцу.
- `/admin/...` — админка: редактирование доступно только после ввода пароля администратора.
