# График объектов 2026

Веб-приложение для администратора и сотрудников. На текущем этапе все данные хранятся **только в localStorage** в одном ключе: `scheduleAppData`.

## Структура проекта

```text
src/
  components/
    Layout.tsx
    ScheduleTable.tsx
  pages/
    AdminMonthPage.tsx
    EmployeesPage.tsx
    ObjectsPage.tsx
    MePage.tsx  # страница просмотра (свои и коллег)
  services/
    dataService.ts
  utils/
    constants.ts
    date.ts
  types.ts
  App.tsx
  main.tsx
  styles.css
```

## Что реализовано

- Маршруты:
  - `/admin/2026/01` ... `/admin/2026/12`
  - `/admin/employees`
  - `/admin/objects`
  - `/viewer` — страница сотрудников (просмотр своих и коллег)
- Русская локализация интерфейса и дней недели.
- Таблица графика: сотрудники по вертикали, дни месяца по горизонтали.
- Выбор значения в ячейке:
  - объект
  - спец-значения: Выходной (В), Отпуск (О), Больничный (Б), Учеба (У)
- Массовое редактирование:
  - выделение диапазона мышью
  - кнопки: «Проставить выбранное», «Очистить выделенное»
- Поиск сотрудника в месячном графике: отображаются только строки найденных сотрудников.
- Экспорт текущего месяца в Excel (CSV) кнопкой «Выгрузить Excel (CSV)».
- Редактирование доступно только после ввода пароля администратора.
- Подсветка выходных (суббота/воскресенье).
- Админ-страницы сотрудников и объектов:
  - добавление
  - редактирование
  - удаление
  - деактивация/активация
- Публикация месяца:
  - при публикации пустые ячейки автоматически становятся «Выходной»
- Страница сотрудников (`/viewer`):
  - при открытии автоматически выбирается текущий месяц из системы пользователя
  - просмотр своего графика и графиков коллег
  - поиск сотрудника по ФИО
  - поиск по конкретному дню для быстрой навигации по таблице
  - выгрузка Excel (CSV) доступна всем (без ограничений по ролям)
  - проверка заполнения объектов по дням (как в просмотре, так и в администрировании)
  - только опубликованные месяцы, read-only

## Как открыть проект

1. Установить зависимости:
   ```bash
   npm install
   ```
2. Запустить dev-сервер:
   ```bash
   npm run dev
   ```
3. Открыть URL из терминала (обычно `http://localhost:5173`).


## Подключение Firebase (подготовка к переносу с localStorage)

1. Скопируйте шаблон переменных окружения:
   ```bash
   cp .env.example .env.local
   ```
2. Значения в `.env.example` уже заполнены вашим `firebaseConfig` (при необходимости обновите).
3. Убедитесь, что в Firebase включены:
   - Firestore Database
   - Authentication → Email/Password
4. В проект добавлен модуль `src/services/firebase.ts` с `firebaseConfig` и проверкой `isFirebaseConfigured()`.
5. После настройки переменных приложение автоматически работает в режиме Firestore-first (с локальным fallback).

Сейчас включен режим **Firestore-first с локальным fallback**:
- каждое изменение данных записывается в `localStorage` и автоматически отправляется в Firestore (`appData/main`);
- если Firestore временно недоступен, сервис повторяет отправку автоматически;
- при старте выполняется попытка подтянуть актуальный snapshot из Firestore;
- ручные методы `pullFromFirestore()` и `pushToFirestore()` сохранены для принудительной синхронизации.

Таким образом, приложение уже работает как клиент БД без необходимости переписывать UI-слой.

## Где лежат данные

Все данные лежат в localStorage в ключе:

- `scheduleAppData`

Структура соответствует формату:

```json
{
  "employees": [{ "id": "...", "full_name": "...", "active": true, "token": "..." }],
  "objects": [{ "id": "...", "name_ru": "...", "short_ru": "...", "active": true }],
  "months": {
    "2026-01": {
      "status": "draft",
      "entries": {
        "employeeId_2026-01-01": {
          "kind": "OBJECT",
          "object_id": "..."
        }
      }
    }
  }
}
```

## Как очистить localStorage

В DevTools браузера (Console):

```js
localStorage.removeItem('scheduleAppData');
```

или полностью:

```js
localStorage.clear();
```

## Как дальше развивать БД/API

Архитектурно используется единый слой данных: `src/services/dataService.ts`.

Сейчас UI вызывает только методы `dataService`, поэтому можно развивать backend без масштабного переписывания компонентов.
Дальнейшие шаги:

1. Разделить snapshot `appData/main` на отдельные коллекции (админы/сотрудники/объекты/месяцы) для конкурентной работы.
2. Перевести ключевые методы сервиса на асинхронные операции (`Promise`) с явными статусами загрузки/ошибок в UI.
3. Добавить авторизацию Firebase Auth и правила Firestore по `admin_id`.
4. При необходимости заменить Firestore REST на Firebase SDK или собственный backend API (интерфейс `dataService` останется точкой абстракции).

## Пароль администратора

Для доступа к редактированию админ-страниц требуется пароль:

- `admin2026`

После входа сессия сохраняется в localStorage (`scheduleAdminSessionId`). Кнопка «Выйти из администратирования» сбрасывает сессию.

## Страницы

- `/viewer` — страница сотрудников: можно смотреть свой график и графики коллег, фильтровать по ФИО и месяцу, а также выгружать Excel (CSV).
- `/admin/...` — администрирование выбранного администратора (переключение вкладками в шапке).
- Управление администраторами (`/admin/admins`) доступно только главному админу: добавление, удаление, смена паролей.

## Проверка заполнения объектов

Для каждого дня месяца выполняется автоматическая проверка: каждый активный объект должен быть назначен минимум одному сотруднику.

- Проверка показывается в админке при редактировании.
- Та же проверка показывается на странице просмотра сотрудников.


## Мульти-админы

- У каждого администратора свои сотрудники, объекты и графики.
- Переключение между администраторами выполняется табами в верхней части страницы.
- Редактирование разделов `/admin/...` доступно только после ввода пароля выбранного администратора.
- Только главный администратор (Епиванов А В) управляет другими админами (создание/удаление/смена пароля/редактирование).
